# Лабораторная работа №1. Диагностика устройств хранения

**Цель:** Научиться выявлять проблемы с накопителями (HDD/SSD) с помощью SMART, анализа журналов и сканирования поверхности.

**Продолжительность:** 1,5–2 часа.

**Оборудование:** Виртуальная машина с Debian/Ubuntu, дополнительный виртуальный диск (например, 2 ГБ) для экспериментов.

---

## Теоретическая справка

- **SMART** (Self-Monitoring, Analysis and Reporting Technology) — система самодиагностики накопителей. Позволяет оценить состояние диска и предсказать отказ.
- **Ключевые SMART-атрибуты:**
  - `Reallocated_Sector_Ct` (ID 5) — переназначенные сектора (любое ненулевое значение — тревога)
  - `Current_Pending_Sector` (ID 197) — секторы, ожидающие переназначения
  - `Offline_Uncorrectable` (ID 198) — невосстановимые секторы
- **badblocks** — утилита для сканирования поверхности диска на наличие повреждённых блоков.
- **Системные журналы** — первый источник информации об аппаратных ошибках (`dmesg`, `journalctl`).

---

## Подготовка стенда

Установите необходимые пакеты:

```bash
sudo apt update
sudo apt install -y smartmontools util-linux
```

Добавьте в виртуальную машину **второй виртуальный диск** (например, 2 ГБ). В системе он появится как `/dev/sdb`.

## Скрипт поломки

Создайте скрипт `break_storage.sh`, который **имитирует** проблемы с диском (в реальной виртуальной среде мы не можем физически повредить диск, поэтому создаём «проблемный» образ и эмулируем ошибки):

```bash
#!/bin/bash
# Скрипт создаёт тестовый диск с "повреждёнными" блоками

echo "=== СОЗДАНИЕ ТЕСТОВОГО ДИСКА С ПРОБЛЕМАМИ ==="

# 1. Создаём файл-образ для тестового диска
dd if=/dev/zero of=/tmp/test_disk.img bs=1M count=200
LOOP=$(sudo losetup -f --show /tmp/test_disk.img)
echo "Создано loop-устройство: $LOOP"

# 2. Создаём файловую систему
sudo mkfs.ext4 -F $LOOP

# 3. Монтируем и создаём тестовые файлы
sudo mkdir -p /mnt/test_disk
sudo mount $LOOP /mnt/test_disk
echo "Тестовые данные" | sudo tee /mnt/test_disk/testfile.txt
sudo dd if=/dev/urandom of=/mnt/test_disk/data.bin bs=1M count=50

# 4. Имитация повреждённых блоков (принудительная запись в "плохие" места)
sudo dd if=/dev/urandom of=$LOOP bs=512 seek=1000 count=10 conv=notrunc 2>/dev/null

# 5. Размонтируем
sudo umount /mnt/test_disk

echo "=== ТЕСТОВЫЙ ДИСК С ПРОБЛЕМАМИ СОЗДАН ==="
echo "Устройство: $LOOP"
echo "Для диагностики используйте:"
echo "  sudo smartctl -a $LOOP"
echo "  sudo badblocks -sv $LOOP"
```

Выполните скрипт:

```bash
chmod +x break_storage.sh
./break_storage.sh
```

## Пошаговая диагностика

### Шаг 1. Анализ системных журналов

Проверьте, нет ли сообщений об ошибках ввода-вывода:

```bash
# Просмотр ошибок в журнале ядра
dmesg -T | grep -iE "i/o error|read error|write error|sector|bad block"

# Просмотр системного журнала
sudo journalctl -xb | grep -iE "i/o error|ata|scsi|sd"
```

**Ожидаемый результат:** Вы увидите сообщения, указывающие на проблемы с чтением/записью на тестовом устройстве.

---

### Шаг 2. Проверка SMART-информации

Определите, какое устройство соответствует вашему тестовому диску (в примере — `/dev/loop0`, но у вас может быть другой номер):

```bash
sudo losetup -l
```

Получите SMART-информацию (для loop-устройств SMART может не поддерживаться, но для реальных дисков команда будет работать):

```bash
# Для реального диска:
sudo smartctl -a /dev/sdb

# Для тестового loop-устройства (если SMART не поддерживается, переходите к badblocks):
sudo smartctl -a /dev/loop0 2>/dev/null || echo "SMART не поддерживается для loop-устройств"
```

Проверьте общее состояние:

```bash
sudo smartctl -H /dev/sdb
```

**Ожидаемый результат:** Если диск здоров — `SMART overall-health self-assessment test result: PASSED`. Если есть проблемы — `FAILED`.

---

### Шаг 3. Запуск тестов SMART

Запустите короткий тест:

```bash
sudo smartctl -t short /dev/sdb
```

Подождите 2–3 минуты и посмотрите результаты:

```bash
sudo smartctl -l selftest /dev/sdb
```

**Ожидаемый результат:** В таблице self-test появится запись о завершённом тесте с состоянием `Completed without error` или `Completed: read failure`.

---

### Шаг 4. Сканирование поверхности (badblocks)

**Важно:** badblocks следует запускать **на размонтированном** разделе, чтобы избежать повреждения данных.

Если у вас есть раздел на тестовом диске (например, `/dev/sdb1`), размонтируйте его:

```bash
sudo umount /dev/sdb1 2>/dev/null
```

Запустите **недеструктивное** сканирование (только чтение):

```bash
sudo badblocks -sv /dev/sdb1
```

Для более тщательной проверки с записью и чтением (разрушает данные!):

```bash
sudo badblocks -wsv /dev/sdb1
```

**Ожидаемый результат:** badblocks покажет список повреждённых блоков (если они есть).

---

### Шаг 5. Проверка файловой системы

Проверьте целостность файловой системы (только чтение):

```bash
sudo fsck -n /dev/sdb1
```

**Ожидаемый результат:** fsck сообщит о чистоте файловой системы или найденных ошибках.

---

### Шаг 6. Составление отчёта

Запишите в отчёт:

- Результаты `dmesg` и `journalctl`;
- SMART-статус и критические атрибуты;
- Результаты тестов SMART;
- Результаты `badblocks`;
- Результаты `fsck`.

**Вывод:** Определите, требует ли диск замены или обслуживания.

# Лабораторная работа №2. Проверка диска и обслуживание файловых систем

**Цель:** Научиться проверять целостность файловых систем, исправлять ошибки и выполнять профилактическое обслуживание.

**Продолжительность:** 1,5–2 часа.

**Оборудование:** ВМ с Debian/Ubuntu, дополнительный диск с ext4.

---

## Теоретическая справка

- **fsck** (File System Check) — основная утилита для проверки и восстановления файловых систем.
- **e2fsck** — версия fsck для файловых систем ext2/ext3/ext4.
- **badblocks** — может использоваться совместно с e2fsck для изоляции повреждённых блоков.
- **fstrim** — утилита для SSD-дисков, очищает неиспользуемые блоки.

## Скрипт поломки

Создайте скрипт `break_filesystem.sh`, который повреждает суперблок и некоторые структуры файловой системы:

```bash
#!/bin/bash
# Скрипт повреждает файловую систему на тестовом разделе

echo "=== ПОВРЕЖДЕНИЕ ФАЙЛОВОЙ СИСТЕМЫ ==="

# 1. Создаём тестовый образ
dd if=/dev/zero of=/tmp/fs_test.img bs=1M count=100
LOOP=$(sudo losetup -f --show /tmp/fs_test.img)
echo "Создано устройство: $LOOP"

# 2. Создаём файловую систему ext4
sudo mkfs.ext4 -F $LOOP

# 3. Монтируем и создаём файлы
sudo mkdir -p /mnt/fs_test
sudo mount $LOOP /mnt/fs_test
for i in {1..20}; do
    echo "File $i" | sudo tee /mnt/fs_test/file_$i.txt > /dev/null
done
sudo umount /mnt/fs_test

# 4. Повреждаем суперблок (записываем случайные данные в начало раздела)
sudo dd if=/dev/urandom of=$LOOP bs=4096 count=1 conv=notrunc 2>/dev/null

echo "=== ФАЙЛОВАЯ СИСТЕМА ПОВРЕЖДЕНА ==="
echo "Устройство: $LOOP"
echo "При попытке смонтировать появится ошибка."
echo "Для восстановления используйте:"
echo "  sudo fsck -y $LOOP"
```

Выполните:

```bash
chmod +x break_filesystem.sh
./break_filesystem.sh
```

```

**Ожидаемый результат:** fsck сообщит о невозможности прочитать суперблок или о других ошибках.

### Шаг 3. Поиск резервных суперблоков

Для ext4 резервные копии суперблока хранятся в определённых позициях. Найдите их:

Если это не помогло, попробуйте другой номер из списка.

```

**Ожидаемый результат:** fsck исправит найденные ошибки и сообщит об успешном завершении.

---

### Шаг 6. Проверка и монтирование

**Ожидаемый результат:** Файловая система смонтирована, файлы (возможно, не все) видны.

## Скрипт восстановления (для автоматизации)

Создайте `fix_filesystem.sh`:

```bash
#!/bin/bash
DEVICE=${1:-/dev/loop0}

echo "=== ВОССТАНОВЛЕНИЕ ФАЙЛОВОЙ СИСТЕМЫ ==="
echo "Устройство: $DEVICE"

# Поиск резервных суперблоков
echo "Поиск резервных суперблоков..."
sudo mke2fs -n $DEVICE 2>/dev/null | grep -i "superblock" | head -5

# Попытка восстановления с резервным суперблоком
echo "Попытка восстановления с резервным суперблоком 32768..."
sudo e2fsck -b 32768 -y $DEVICE

# Если не помогло — полное восстановление
if [ $? -ne 0 ]; then
    echo "Полное восстановление..."
    sudo fsck -y $DEVICE
fi

echo "=== ГОТОВО ==="
```

# Лабораторная работа №3. Восстановление потерянных данных

**Цель:** Научиться восстанавливать удалённые файлы и повреждённые разделы с помощью TestDisk, extundelete и PhotoRec.

**Продолжительность:** 2 часа.

**Оборудование:** ВМ с Debian/Ubuntu, дополнительный диск с ext4 и тестовыми файлами.

---

## Теоретическая справка

- **TestDisk** — мощная утилита для восстановления потерянных разделов и исправления загрузочных секторов.
- **extundelete** — восстанавливает удалённые файлы с файловых систем ext3/ext4.
- **PhotoRec** — восстанавливает файлы по их сигнатурам (file carving), работает с любыми файловыми системами.

## Скрипт поломки

Создайте скрипт `break_data.sh`, который удаляет файлы и повреждает таблицу разделов:

```bash
#!/bin/bash
# Скрипт создаёт тестовый раздел с файлами, затем "случайно" удаляет их

echo "=== СОЗДАНИЕ ТЕСТОВОГО РАЗДЕЛА С ФАЙЛАМИ ==="

# 1. Создаём образ
dd if=/dev/zero of=/tmp/data_test.img bs=1M count=200
LOOP=$(sudo losetup -f --show /tmp/data_test.img)

# 2. Создаём таблицу разделов и раздел
sudo parted -s $LOOP mklabel msdos
sudo parted -s $LOOP mkpart primary ext4 1MiB 100%
sudo partprobe $LOOP

# 3. Создаём файловую систему
sudo mkfs.ext4 -F ${LOOP}p1

# 4. Монтируем и создаём тестовые файлы
sudo mkdir -p /mnt/data_test
sudo mount ${LOOP}p1 /mnt/data_test

echo "Создание тестовых файлов..."
for i in {1..30}; do
    echo "Это тестовый файл номер $i" | sudo tee /mnt/data_test/doc_$i.txt > /dev/null
    dd if=/dev/urandom of=/mnt/data_test/data_$i.bin bs=1K count=10 2>/dev/null
done

# 5. Создаём важные файлы
echo "Важный документ" | sudo tee /mnt/data_test/important.txt
echo "Пароли: admin:secret" | sudo tee /mnt/data_test/secrets.txt

# 6. Удаляем несколько файлов (имитация случайного удаления)
sudo rm -f /mnt/data_test/doc_5.txt /mnt/data_test/doc_12.txt /mnt/data_test/data_15.bin

# 7. Размонтируем
sudo umount /mnt/data_test

echo "=== ТЕСТОВЫЙ РАЗДЕЛ СОЗДАН ==="
echo "Устройство: ${LOOP}p1"
echo "Удалены файлы: doc_5.txt, doc_12.txt, data_15.bin"
echo ""
echo "Для восстановления используйте:"
echo "  sudo extundelete ${LOOP}p1 --restore-file doc_5.txt"
echo "  sudo testdisk ${LOOP}"
```

Выполните:

```bash
chmod +x break_data.sh
./break_data.sh
```

# Лабораторная работа №4. Работа с BTRFS

**Цель:** Научиться диагностировать и восстанавливать повреждённые файловые системы BTRFS, использовать встроенные инструменты восстановления.

**Продолжительность:** 2 часа.

**Оборудование:** ВМ с Debian/Ubuntu, дополнительный диск для BTRFS.

---

## Теоретическая справка

- **BTRFS** — современная файловая система с поддержкой снапшотов, сжатия, проверки целостности и RAID.
- **btrfs check** — проверка целостности файловой системы.
- **btrfs rescue** — инструменты для восстановления повреждённых томов.
- **btrfs restore** — извлечение файлов с повреждённой файловой системы.
- **btrfs scrub** — проверка всех данных и метаданных на наличие ошибок.

---

## Скрипт поломки

Создайте скрипт `break_btrfs.sh`:

```bash
#!/bin/bash
# Скрипт создаёт BTRFS-раздел и повреждает его

echo "=== СОЗДАНИЕ BTRFS-РАЗДЕЛА ==="

# 1. Создаём образ
dd if=/dev/zero of=/tmp/btrfs_test.img bs=1M count=500
LOOP=$(sudo losetup -f --show /tmp/btrfs_test.img)

# 2. Создаём BTRFS
sudo mkfs.btrfs -f $LOOP

# 3. Монтируем и создаём файлы
sudo mkdir -p /mnt/btrfs_test
sudo mount $LOOP /mnt/btrfs_test

echo "Создание тестовых файлов и снапшотов..."
for i in {1..20}; do
    echo "File $i" | sudo tee /mnt/btrfs_test/file_$i.txt > /dev/null
done

# Создаём подтом и снапшот
sudo btrfs subvolume create /mnt/btrfs_test/@subvol
echo "Subvolume file" | sudo tee /mnt/btrfs_test/@subvol/subfile.txt > /dev/null
sudo btrfs subvolume snapshot /mnt/btrfs_test/@subvol /mnt/btrfs_test/@snap1

sudo umount /mnt/btrfs_test

# 4. Повреждаем метаданные (записываем случайные данные в начало)
sudo dd if=/dev/urandom of=$LOOP bs=4096 count=10 conv=notrunc 2>/dev/null

echo "=== BTRFS-РАЗДЕЛ ПОВРЕЖДЕН ==="
echo "Устройство: $LOOP"
echo ""
echo "Для диагностики используйте:"
echo "  sudo btrfs check $LOOP"
echo "  sudo btrfs rescue chunk-recover $LOOP"
echo "  sudo btrfs restore $LOOP /tmp/restored/"
```

## Пошаговая диагностика и восстановление

### Шаг 1. Попытка монтирования в режиме восстановления

```bash
sudo mount -o recovery /dev/loop0 /mnt/btrfs_test
```

**Ожидаемый результат:** Возможна ошибка монтирования.

---

### Шаг 2. Проверка файловой системы (только чтение)

```bash
sudo btrfs check /dev/loop0
```

**Ожидаемый результат:** btrfs check сообщит о найденных ошибках в метаданных.

---

### Шаг 3. Восстановление суперблока (btrfs rescue)

**3.1. Очистка повреждённого лога**

Если файловая система не монтируется из-за повреждённого лога:

```bash
sudo btrfs rescue zero-log /dev/loop0
```

**Ожидаемый результат:** Лог очищен, файловая система может смонтироваться.

**3.2. Восстановление chunk-дерева**

```bash
sudo btrfs rescue chunk-recover /dev/loop0
```

**Ожидаемый результат:** Восстановление chunk-дерева (может занять время).

---

### Шаг 4. Извлечение данных (btrfs restore)

Если файловая система не поддаётся восстановлению, извлеките данные:

```bash
# Просмотр содержимого без восстановления
sudo btrfs restore -l /dev/loop0

# Восстановление всех файлов
sudo mkdir -p /tmp/btrfs_restored
sudo btrfs restore -x /dev/loop0 /tmp/btrfs_restored/
```

**Ожидаемый результат:** Файлы извлечены в указанную директорию.

Параметры `btrfs restore`:
- `-l` — только список файлов (без восстановления)
- `-x` — восстановление файлов
- `-s` — восстановление снапшотов
- `-m` — восстановление метаданных

---

### Шаг 5. Проверка целостности (btrfs scrub)

Если система смонтировалась, выполните проверку:

```bash
sudo btrfs scrub start /mnt/btrfs_test
sudo btrfs scrub status /mnt/btrfs_test
```

**Ожидаемый результат:** scrub найдёт и исправит ошибки (если есть резервные копии).

---

### Шаг 6. Работа со снапшотами

Если есть снапшоты, их можно использовать для восстановления:

```bash
# Список снапшотов
sudo btrfs subvolume list /mnt/btrfs_test

# Восстановление из снапшота
sudo btrfs subvolume snapshot /mnt/btrfs_test/@snap1 /mnt/btrfs_test/@restored
```

## Скрипт восстановления BTRFS

Создайте `fix_btrfs.sh`:

```bash
#!/bin/bash
DEVICE=${1:-/dev/loop0}
RESTORE_DIR=${2:-/tmp/btrfs_restored}

echo "=== ВОССТАНОВЛЕНИЕ BTRFS ==="
echo "Устройство: $DEVICE"

# 1. Попытка монтирования в recovery
echo "1. Попытка монтирования в recovery mode..."
sudo mkdir -p /mnt/btrfs_recovery
sudo mount -o recovery $DEVICE /mnt/btrfs_recovery 2>/dev/null
if [ $? -eq 0 ]; then
    echo "   УСПЕШНО! Данные доступны в /mnt/btrfs_recovery"
    exit 0
fi

# 2. Очистка лога
echo "2. Очистка повреждённого лога..."
sudo btrfs rescue zero-log $DEVICE

# 3. Попытка монтирования после очистки лога
echo "3. Повторная попытка монтирования..."
sudo mount $DEVICE /mnt/btrfs_recovery 2>/dev/null
if [ $? -eq 0 ]; then
    echo "   УСПЕШНО! Данные доступны в /mnt/btrfs_recovery"
    exit 0
fi

# 4. Восстановление chunk-дерева
echo "4. Восстановление chunk-дерева..."
sudo btrfs rescue chunk-recover -y $DEVICE

# 5. Извлечение данных
echo "5. Извлечение данных с помощью btrfs restore..."
sudo mkdir -p $RESTORE_DIR
sudo btrfs restore -x $DEVICE $RESTORE_DIR/

echo "=== ГОТОВО ==="
echo "Данные восстановлены в $RESTORE_DIR"
```
