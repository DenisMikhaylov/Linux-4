# Лабораторная работа. Диагностика аппаратных неисправностей в Linux

**Продолжительность:** 2 академических часа

**Оборудование:** Виртуальная машина с Debian 11/12 (или любым дистрибутивом на основе systemd)

---

## Цель работы

Научиться выявлять, диагностировать и документировать аппаратные проблемы в Linux с использованием штатных средств операционной системы. В ходе работы вы освоите:

- анализ системных журналов для поиска аппаратных ошибок;
- сбор и интерпретацию информации об оборудовании;
- диагностику состояния дисков с помощью SMART;
- мониторинг температур и работы процессора;
- проверку оперативной памяти.

---

## Теоретическая справка

Аппаратные неисправности могут проявляться по-разному: от внезапных перезагрузок и «зависаний» до ошибок ввода-вывода и постепенной деградации производительности. Linux предоставляет широкий набор инструментов для диагностики оборудования на всех уровнях — от журналов ядра до специализированных утилит.

Основные компоненты, подлежащие диагностике:

| Компонент | Признаки неисправности | Инструменты |
|-----------|------------------------|-------------|
| **Дисковая подсистема** | Ошибки чтения/записи, медленная работа, сбой при загрузке | `smartctl`, `dmesg`, `fsck` |
| **Оперативная память** | Случайные сбои, kernel panic, ошибки сегментации | `memtest86+`, `dmesg` (EDAC/MCE) |
| **Процессор/температура** | Троттлинг, внезапные выключения, высокая нагрузка | `sensors`, `lscpu`, `dmesg` |
| **Сетевое оборудование** | Потеря пакетов, отсутствие интерфейса, ошибки драйвера | `lspci`, `lsusb`, `dmesg`, `ip` |
| **Системная плата/BIOS** | Проблемы с определением устройств, ошибки ACPI | `dmidecode`, `dmesg` |

---

## Подготовка стенда

Убедитесь, что на вашей виртуальной машине установлены необходимые пакеты:

```bash
sudo apt update
sudo apt install -y lshw dmidecode smartmontools lm-sensors memtest86+ inxi hwinfo
```

> **Примечание:** В виртуальной среде часть аппаратных датчиков может быть недоступна. В таких случаях мы будем работать с теми данными, которые эмулирует гипервизор.

## Часть 1. Сбор общей информации об оборудовании (20 минут)

### Шаг 1. Базовые команды для получения информации о системе

Выполните следующие команды и запишите результаты в отчёт:

**1.1. Информация о процессоре:**
```bash
lscpu
```
Обратите внимание на: модель процессора, количество ядер, архитектуру.

**1.2. Информация об оперативной памяти:**
```bash
free -h
cat /proc/meminfo | grep -E "^(MemTotal|SwapTotal|MemAvailable)"
```

**1.3. Список блочных устройств (диски и разделы):**
```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT,MODEL
```

**1.4. Полный список оборудования в кратком виде:**
```bash
sudo lshw -short
```
Эта команда покажет иерархическое дерево всех устройств.

---

### Шаг 2. Детальная информация об оборудовании

**2.1. Информация из DMI (Desktop Management Interface):**
```bash
sudo dmidecode -t system
```
Вывод содержит данные о производителе, модели и серийном номере системы.

**2.2. Информация о BIOS:**
```bash
sudo dmidecode -t bios
```

**2.3. PCI-устройства (включая сетевые карты, контроллеры):**
```bash
lspci -v
```

**2.4. USB-устройства:**
```bash
lsusb
```

**2.5. Развёрнутый отчёт с помощью inxi:**
```bash
sudo inxi -Fxz
```
Опция `-F` даёт полную информацию, `-x` — дополнительные детали, `-z` — скрывает серийные номера.

---

### Шаг 3. Сохранение отчёта

Создайте файл с полным отчётом об оборудовании:

```bash
sudo lshw -html > /tmp/hardware_report.html
```

Откройте этот файл в браузере для визуального просмотра. Сохраните копию в свою рабочую директорию.

## Часть 2. Анализ системных журналов на предмет аппаратных ошибок (25 минут)

### Шаг 4. Просмотр журнала ядра

Журнал ядра (`dmesg`) содержит сообщения об обнаружении устройств, ошибках драйверов и проблемах с оборудованием.

**4.1. Просмотр всех сообщений ядра с человекочитаемым временем:**
```bash
dmesg -T | less
```

**4.2. Фильтрация сообщений об ошибках и предупреждениях:**
```bash
dmesg -T | grep -iE "error|fail|warning|fault|irq|dma|timeout|corrupt"
```

**4.3. Поиск ошибок, связанных с дисками:**
```bash
dmesg -T | grep -iE "sda|sdb|hd|sd|ata|scsi|i/o error"
```

**4.4. Поиск ошибок памяти (EDAC — Error Detection and Correction):**
```bash
dmesg -T | grep -iE "edac|mce|machine check|ecc"
```
Если система поддерживает ECC-память, здесь могут быть сообщения об исправленных ошибках.

**4.5. Поиск проблем с USB-устройствами:**
```bash
dmesg -T | grep -i usb | grep -iE "error|fail|reset|timeout"
```

**4.6. Просмотр только сообщений об ошибках (уровень ERR и выше):**
```bash
dmesg -l err
```


---

### Шаг 5. Анализ системного журнала

**5.1. Просмотр системного журнала:**
```bash
sudo journalctl -xb -p err
```


**5.2. Поиск аппаратных ошибок в системном журнале:**
```bash
sudo journalctl -xb | grep -iE "hardware|device|firmware|acpi|pci|usb|ata|scsi"
```

**5.3. Просмотр журнала за предыдущую загрузку (если система перезагружалась):**
```bash
sudo journalctl -b -1 -p err
```


**5.4. Поиск сообщений о сбоях дисков:**
```bash
sudo grep -iE "i/o error|read error|write error|sector|bad block" /var/log/syslog
```

### Шаг 6. Интерпретация результатов

Запишите в отчёт:

- Какие ошибки были найдены?
- С какими устройствами они связаны?
- Каков уровень критичности этих ошибок?

## Часть 3. Диагностика дисков с помощью SMART (25 минут)

### Шаг 7. Просмотр SMART-информации

**7.1. Определите имя вашего диска:**
```bash
lsblk
```
Обычно это `/dev/sda` или `/dev/nvme0n1`.

**7.2. Проверка поддержки SMART:**
```bash
sudo smartctl -i /dev/sda
```

**7.3. Просмотр полной SMART-информации:**
```bash
sudo smartctl -a /dev/sda
```


Обратите внимание на следующие атрибуты:

| Атрибут | ID | Что означает | Критическое значение |
|---------|----|--------------|---------------------|
| Reallocated_Sector_Ct | 5 | Количество переназначенных секторов | > 0 — тревожный сигнал |
| Current_Pending_Sector | 197 | Секторы, ожидающие переназначения | > 0 — срочная замена |
| Offline_Uncorrectable | 198 | Невосстановимые секторы | > 0 — диск умирает |
| Raw_Read_Error_Rate | 1 | Частота ошибок чтения | Рост — проблема |
| Seek_Error_Rate | 7 | Частота ошибок позиционирования | Рост — проблема |

**7.4. Проверка общего состояния диска:**
```bash
sudo smartctl -H /dev/sda
```

Если вывод содержит `SMART overall-health self-assessment test result: PASSED` — диск считается здоровым. Если `FAILED` — требуется немедленная замена.

---

### Шаг 8. Запуск тестов SMART

**8.1. Запуск короткого теста (занимает около 2 минут):**
```bash
sudo smartctl -t short /dev/sda
```

**8.2. Проверка результатов теста (подождите 2-3 минуты):**
```bash
sudo smartctl -l selftest /dev/sda
```

**8.3. Запуск расширенного теста (может занять часы — пропустите, если нет времени):**
```bash
sudo smartctl -t long /dev/sda
```

---

### Шаг 9. Проверка файловой системы

Если есть подозрения на повреждение файловой системы:

```bash
sudo fsck -n /dev/sda1
```

Опция `-n` выполняет проверку без внесения изменений.

## Часть 4. Мониторинг температуры и состояния процессора (20 минут)

### Шаг 10. Настройка и использование lm-sensors

**10.1. Автоматическое обнаружение датчиков:**
```bash
sudo sensors-detect
```
На все вопросы отвечайте `YES` (или просто нажимайте Enter для принятия значений по умолчанию).

**10.2. Просмотр температуры:**
```bash
sensors
```


Обратите внимание на:
- Температуру процессора (обычно `Core 0`, `Core 1` и т.д.);
- Температуру материнской платы;
- Скорость вращения вентиляторов (если доступно).

**Нормальные значения:** для процессора в состоянии покоя — 30–50°C, под нагрузкой — до 80°C. Превышение 90°C может указывать на проблемы с охлаждением.

---

### Шаг 11. Информация о процессоре

**11.1. Текущая частота процессора:**
```bash
cat /proc/cpuinfo | grep "MHz"
```

**11.2. Проверка троттлинга (снижения частоты из-за перегрева):**
```bash
dmesg -T | grep -i "thermal\|throttle\|temperature"
```

**11.3. Просмотр информации о тепловом состоянии (если поддерживается):**
```bash
cat /sys/class/thermal/thermal_zone*/temp
```

## Часть 5. Проверка оперативной памяти (15 минут)

### Шаг 12. Использование memtest86+

**Важно:** Memtest86+ требует перезагрузки системы и не может быть запущен из работающей ОС. Для виртуальных машин этот тест может быть недоступен — в таком случае перейдите к альтернативному варианту.

**12.1. Убедитесь, что memtest86+ установлен:**
```bash
dpkg -l | grep memtest86+
```


**12.2. Добавление Memtest86+ в меню GRUB (обычно устанавливается автоматически):**
```bash
sudo update-grub
```

**12.3. Перезагрузитесь и выберите в меню GRUB пункт "Memory test (memtest86+)".**

**12.4. Запустите тест минимум на 1 полный проход (может занять 10–30 минут).**

Если Memtest86+ недоступен в виртуальной среде, используйте альтернативный метод:

**Альтернативный метод (запуск из работающей системы):**
```bash
sudo apt install stress-ng
sudo stress-ng --vm 2 --vm-bytes 512M --timeout 60s
```
Эта команда создаёт нагрузку на память. Если система падает или появляются ошибки сегментации — это может указывать на проблемы с памятью.

## Часть 6. Практическое задание: «Поломка и восстановление» (15 минут)

### Шаг 13. Имитация аппаратной проблемы

> **Внимание!** Этот шаг выполняется только на виртуальной машине. Никогда не выполняйте эти команды на рабочем сервере!

Создайте скрипт `simulate_hardware_issue.sh`:

```bash
#!/bin/bash
# Имитация ошибок диска путём создания повреждённых секторов (только в тестовой среде!)

echo "Создание тестового файла для имитации проблем с диском..."
dd if=/dev/zero of=/tmp/test_disk.img bs=1M count=100

# Создание loop-устройства
sudo losetup -f /tmp/test_disk.img
LOOP=$(sudo losetup -l | grep test_disk.img | awk '{print $1}')

# Создание файловой системы
sudo mkfs.ext4 $LOOP

# Имитация ошибок путём принудительной записи сбойных секторов (только для демонстрации)
echo "Имитация ошибок завершена. Теперь выполните диагностику."
```

Сделайте скрипт исполняемым и выполните:

```bash
chmod +x simulate_hardware_issue.sh
./simulate_hardware_issue.sh
```

### Шаг 14. Диагностика созданной проблемы

Выполните диагностику созданного устройства:

```bash
# Поиск ошибок в журнале
dmesg -T | grep -i "loop\|ext4\|I/O error"

# Проверка файловой системы
sudo fsck -n $LOOP

# Просмотр SMART-информации (если поддерживается)
sudo smartctl -a $LOOP 2>/dev/null || echo "SMART не поддерживается для loop-устройств"
```
